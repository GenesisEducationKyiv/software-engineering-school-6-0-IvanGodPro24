# ADR-001: Вибір бази даних для зберігання підписок

**Статус:** Прийнято

**Дата:** 2026-05-06

**Автор:** Ivan Nepotachev

## Контекст

Системі необхідно надійно зберігати дані користувачів, їхні підписки на конкретні GitHub-репозиторії, а також токени підтвердження. Дані мають чітку структуру та реляційні зв'язки (одна підписка стосується одного користувача та одного репозиторію). Крім того, важливо уникати дублювання підписок.

## Розглянуті варіанти

1. **PostgreSQL**
   * **Плюси:** Повна підтримка ACID, механізми унікальних індексів, надійність, інтеграція з Prisma ORM.
   * **Мінуси:** Потребує більше ресурсів системи та налаштування міграцій порівняно з NoSQL рішеннями.
2. **MongoDB**
   * **Плюси:** Гнучкість схеми, швидкий старт.
   * **Мінуси:** Відсутність схеми з коробки, Eventual consistency.
3. **Redis (як основна БД)**
   * **Плюси:** Максимальна швидкість читання/запису.
   * **Мінуси:** Ризик втрати даних при перезавантаженні, відсутність зручних реляційних запитів.

## Прийняте рішення

Обрано **PostgreSQL**.

## Наслідки

**Позитивні:**

* Гарантована цілісність даних завдяки зовнішнім ключам та унікальним індексам `@@unique([email, repositoryId])`.
* Можливість легко масштабувати аналітичні запити в майбутньому.
* Типобезпека на рівні бекенду завдяки генерації клієнта Prisma на основі чіткої SQL-схеми.

**Негативні:**

* Необхідність підтримувати систему міграцій.
* Вищі вимоги до оперативної пам'яті контейнера БД порівняно з SQLite чи NoSQL.
