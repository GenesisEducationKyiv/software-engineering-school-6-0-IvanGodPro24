# ADR-003: Вибір інструменту для розсилки Email-сповіщень

**Статус:** Прийнято

**Дата:** 2026-05-06

**Автор:** Ivan Nepotachev

## Контекст

Основним каналом комунікації системи є електронна пошта. Нам необхідно відправляти листи для підтвердження підписки та сповіщення про нові релізи. Потрібен надійний спосіб інтеграції з поштовими серверами, який дозволить легко тестувати розсилку локально і працювати в production.

## Розглянуті варіанти

1. **Nodemailer + стандартний SMTP**
   - **Плюси:** Найпопулярніший стандарт в екосистемі Node.js, не прив'язує до конкретного вендора, дозволяє легко використовувати сервіси-заглушки (Mailtrap) для локального тестування.
   - **Мінуси:** Не має вбудованої аналітики, потребує ручної обробки HTML-шаблонів.
2. **Vendor-specific API (SendGrid / AWS SES / Resend API клієнти)**
   - **Плюси:** Вбудована аналітика, висока гарантія доставки.
   - **Мінуси:** Жорстка прив'язка до SDK конкретного провайдера, складніше локальне тестування.

## Прийняте рішення

Обрано **Nodemailer** з використанням конфігурації SMTP через змінні середовища.

## Наслідки

**Позитивні:**

- Архітектурна гнучкість: ми можемо змінити поштового провайдера просто змінивши змінні `SMTP_HOST` та `SMTP_PORT` без переписування коду застосунку.
- Безкоштовне та безпечне локальне тестування.

**Негативні:**

- У майбутньому, якщо знадобиться аналітика прочитаних листів, доведеться інтегрувати додаткові механізми або переходити на спеціалізовані API провайдерів.
